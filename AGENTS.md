# Code2Ticket: panduan agent

## Ringkasan
Aplikasi mobile Flutter (tugas akhir Pemrograman Aplikasi Mobile): pengguna memasukkan kode -> tiket undian digital -> draw otomatis terjadwal ->
pemenang dapat diverifikasi lewat hash-chain (commit-reveal). Bahasa antarmuka dan komentar: Indonesia.

## Arsitektur
Flutter (app\) -> HTTPS -> Express (backend\, di Render: https://code2ticket.onrender.com) -> Postgres (Supabase, hanya sebagai database).
Aplikasi tidak memakai Supabase Auth, anon key, maupun akses tabel langsung. SQLite lokal di app untuk cache, riwayat pencarian, pengaturan, dan riwayat chat Asisten (tabel chat_messages, DB lokal v6: cache giveaway memakai prize_value_idr, how_to_participate, organizer_url; tabel cached_draw_results untuk hasil draw offline).
Login/session dibuat sendiri (bukan Firebase/Supabase Auth). Scheduler draw: node-cron + endpoint /internal/tick yang dipanggil tiap menit (Render free bisa tertidur).

- app\      Flutter. lib\core (api, crypto, db, security, session), lib\features (auth, giveaways, tickets, profile, assistant, shell), test\
- backend\  Express (JavaScript ESM). src\ (rute, services, lib), db\ (01_schema.sql, 06_backend.sql, 07_user_photos.sql, 08_prize_value_idr.sql, 09_giveaway_participation.sql, 10_redeem_geo_restricted.sql, 11_organizer_contact.sql, 12_chain_anchors.sql, shim uji), test\ (vitest), scripts\demo-seed.js
- Dokumen (PRD, ERD, Context) ada DI LUAR repo: ..\docs\ (hanya dibaca; jangan disalin ke repo). Istilah RPC di dokumen itu sudah usang;
  bila bertentangan dengan kode, yang berlaku adalah backend\src dan backend\README.md. Laporkan pertentangannya.

Rute: /game = pemilih game (game_chooser_screen.dart), /game/codehunt = hub Buru Kode, /game/chain = level Rakit Rantai; rekor lokal Buru Kode di code_hunt_record.dart (app_settings `codehunt_best`, hanya tampilan).

## Nilai hadiah (rupiah)
- Mata uang DASAR nilai hadiah adalah rupiah bulat (FR-CUR-01): kolom `giveaways.prize_value_idr` (numeric(16,0), 0..100.000.000.000, migrasi backend\db\08_prize_value_idr.sql), field API `prize_value_idr`, model `Giveaway.prizeValueIdr` (int). `prize_value_usd` DEPRECATED: tidak dibaca/ditulis kode dan tidak ada di respons; kolom lama dibiarkan sampai di-drop di migrasi berikutnya. Jangan memakai USD sebagai nilai dasar lagi.
- Admin mengetik rupiah (`Nilai hadiah (Rp)`, pemisah ribuan otomatis, `RupiahInputFormatter`/`parseRupiah` di core\rupiah_input.dart) dan app mengirim integer; backend menerima bilangan bulat 1..100.000.000.000 (`invalid_input` + `field: prize_value_idr`). Nilai tersimpan = nilai yang dilihat pengguna ber-mata-uang IDR (tanpa konversi/pembulatan).
- Tampilan: SEMUA nilai hadiah (kartu, Home, Detail, Asisten) lewat `formatPrize` (core\currency\currency.dart) / `context.money(int?)` (core\display.dart): IDR -> mata uang pilihan lewat kurs Frankfurter (pivot USD: kurs yang ada di RatesController, `RateSet.convert('IDR' -> X)`). Mata uang pilihan tanpa kurs (offline tanpa cache) -> tampil IDR + catatan di RateNote, BUKAN USD. Mata uang bawaan pengguna baru = IDR.
- Filter Discover: `min_value`/`max_value` dan sort `value` di backend memakai rupiah. `DiscoverFilters.minValueIdr/maxValueIdr` selalu rupiah; FilterSheet membaca masukan dalam mata uang tampilan dan mengonversi dengan `prizeToIdr` (minimum dibulatkan ke bawah, maksimum ke atas). Logika konversi tidak boleh ada di layar selain lewat fungsi-fungsi itu.
- Cache SQLite lokal v3: `cached_giveaways.prize_value_idr INTEGER` (migrasi onUpgrade membuang dan membuat ulang tabel cache, serta mengosongkan `chat_messages.related_json`).
- Asisten (backend\src\services\chat.js) memberi model `nilai_rupiah` pada data giveaway.

## Sesi offline (cold start tanpa internet)
- auth_controller.restore(): HANYA 401 (invalid_session) yang menghapus token dan data pengguna. Galat jaringan/timeout/5xx/respons aneh + token lokal + profil tersimpan (app_settings `last_profile`, user_id kosong: id, username, nama, role, foto, xp, level; tanpa email/token/password, ditulis tiap login//auth/me berhasil dan updateUser) -> `AuthController.offlineSession = true` dengan status tetap signedIn; biometric tetap diminta sebelum konten (_unlock). Tanpa profil -> belum masuk, token tidak dihapus.
- Pulih: `revalidate()` (resume di main.dart; respons sukses dari AuthedApi saat offline; AuthedApi menulis -> revalidate dulu). 200 -> online + `backOnline` (Tickets/Giveaways/Discover reload); 401 -> keluar dengan pembersihan; galat jaringan -> tetap offline. `ApiClient.getOnce` = cek sesi tanpa jeda ulang soket.
- Aksi tulis (POST/PUT/PATCH lewat AuthedApi) saat offline -> OfflineRequiredException "Butuh koneksi internet." tanpa mengirim; admin tetap butuh online. SessionStore.readToken menelan galat secure storage (null). clearUserData(userId: null) menghapus semua baris pencarian dan chat; _clear memakai id dari profil tersimpan bila user belum terisi.

- Semua galat transport (SocketException, ClientException, HandshakeException, TlsException, HttpException, OSError) dipetakan ApiClient ke NetworkException; galat mentah tidak boleh lolos ke controller. Sesi offline: GET lewat AuthedApi gagal cepat (tanpa jeda ulang 3+6 dtk). Home/My Tickets/Discover (Giveaways/Tickets/DiscoverController) saat jaringan gagal: cache ada, cache kosong, atau semua sudah berakhir -> daftar kosong + OfflineBanner (state loaded, offline true, muat ulang berkala), BUKAN ErrorState. ErrorState + "Coba lagi" hanya untuk jawaban server yang rusak (`ServerFaultException`: 5xx, bukan JSON, `ok:false`) saat sesi online (`showsOffline` di core\offline.dart); sesi offline selalu tampilan offline. Akar masalah galat "Gagal memuat / Tidak ada koneksi internet." di Home setelah login: ketiga controller memperlakukan cache kosong (server belum punya giveaway/tiket aktif saat terakhir online, jadi tak ada yang tersimpan) sebagai galat, bukan sebagai daftar kosong. `AuthedApi.get` yang gagal jaringan (bukan ServerFault) memanggil `AuthController.markOffline()`: sesi online menjadi offline (tetap signedIn, GET berikutnya gagal cepat tanpa jeda ulang 3+6 dtk, aksi tulis "Butuh koneksi internet.") sampai `revalidate()` berhasil; aksi tulis yang gagal tidak mengubah status. Tes: app\test\offline_empty_cache_test.dart (cold start, resume, refresh dengan cache kosong). Tes boot nyata (main -> restore -> router -> Home, SQLite ffi, tiap jenis galat, biometric aktif/nonaktif): app\test\offline_boot_test.dart; Code2TicketApp punya parameter injeksi (api, sessionStore, db, biometric, poller) khusus tes.
- Hasil Draw offline (DB lokal v6, tabel `cached_draw_results`: PK (user_id, giveaway_id), status, drawn_at_ms, total_tickets, winner_count, winners_json [rank, ticket_number, nama tersamar], cached_at; tanpa seed/token; maks 50 giveaway terbaru per pengguna; dikosongkan di clearUserData saat logout). DrawController (mode default): online -> simpan HANYA hasil final (drawn=true) lewat CacheStore.saveDrawResult; jaringan gagal/sesi offline (showsOffline) -> baca cache + OfflineBanner, atau `notCached` -> EmptyState "Hasil draw belum tersimpan di perangkat..." (bukan ErrorState); ServerFaultException online (5xx, ok:false, verifikasi tak lengkap) tetap ErrorState + "Coba lagi". Penanda "tiketmu" dan gerbang goyang tetap dihitung dari TicketsController/draw_seen (bukan dari cache hasil). Cek Keaslian (`verifyOnly: true`) tidak memakai cache: offline -> "Butuh koneksi internet untuk memeriksa keaslian." Provider<CacheStore> ada di main.dart.

## Cakupan status Discover
`GET /giveaways` publik: tanpa `status` dan tanpa `q` = aktif + akan datang; tanpa `status` dengan `q` = semua status; `status` eksplisit (`active`/`upcoming`/`waiting_draw`/`drawn`/`finished`/`all`, majemuk dipisah koma) dipatuhi persis, nilai lain `invalid_input`. Urutan selalu per kelompok (aktif, akan datang, menunggu draw, selesai), lalu `sort` (bawaan: aktif deadline terdekat, akan datang mulai terdekat, yang berakhir terbaru dulu). Detail: backend\README.md. App: `DiscoverFilters.status` null = chip "Semua" (mengirim `status=all`, semua status; backend tidak diubah), status dan urutan HANYA di sheet filter (`sheet_status_*`, `sheet_sort_*`; tidak ada lagi baris chip status/urutan di layar), baris ringkas `filter_summary` menampilkan chip hapus untuk nilai non-bawaan saja, lencana filter menghitung status dan urutan non-bawaan, "Atur ulang" = status Semua + urutan bawaan; "Terdekat" butuh lokasi (nonaktif + "Butuh lokasi"; tombol `sheet_use_location` menjalankan `enableNearby`). "Selesai" = menunggu draw + sudah diundi (`finished`); kartu tetap membedakan lewat StatusChip. Offline: `applyLocal` memakai aturan dan urutan yang sama (`statusGroupRank`). Home (`GiveawaysController`) memanggil `status=active` dan Peta/"Terdekat" di Home memakai `DiscoverController.activeByDefault` (status bawaan -> hanya aktif), jadi keduanya tidak berubah. Tes: backend\test\discover-status.test.js, app\test\discover_test.dart, map_test.dart, cache_test.dart.

## Jangkar blockchain (Cek Keaslian langkah 5)
Hash blok Commit dan Hasil dijangkarkan ke blockchain publik testnet (bawaan Ethereum Sepolia 11155111, explorer https://sepolia.etherscan.io/tx/{tx}; jaringan lain lewat env ANCHOR_CHAIN_ID/ANCHOR_EXPLORER_TX_URL/ANCHOR_PUBLIC_RPC_URL): transaksi value 0 ke dompet sendiri, data = hex UTF-8 "C2T:" + block_hash, tanpa smart contract. Backend: backend\src\services\anchor.js (viem), tabel `chain_anchors` (backend\db\12_chain_anchors.sql; draw_chain tidak diubah), `GET /giveaways/:id/anchors`. Baris pending ditulis lewat savepoint di transaksi pembuatan blok, dikirim setelah commit + putaran berkala 60 dtk + `/internal/tick`; jangkar TIDAK PERNAH memblokir/menggagalkan pembuatan giveaway, draw, atau redeem (redeem tetap hanya menunggu blok Commit di draw_chain). Idempoten: tx_hash disimpan sebelum siaran dengan syarat `tx_hash is null`; retry backoff, maks. 6 percobaan.
- Env (nilai hanya di Render/.env lokal; .env.example berisi nama saja): ANCHOR_ENABLED (harus `true`), ANCHOR_RPC_URL, ANCHOR_CHAIN_ID, ANCHOR_PRIVATE_KEY, ANCHOR_EXPLORER_TX_URL, ANCHOR_PUBLIC_RPC_URL. Kurang/tidak valid = fitur mati tanpa crash. Kunci privat dan URL RPC ber-key tidak boleh masuk log, respons, last_error, repo, atau fixture tes (tes membuat kunci acak). Cara membuat dompet testnet: backend\README.md "Jangkar blockchain". Alamat dompet pribadi juga jangan ditulis di repo.
- App: app\lib\core\verify\anchor_checker.dart (murni + JSON-RPC lewat http, tanpa paket kripto). Data transaksi dari RPC publik (bawaan app per chain_id; rpc_url server hanya untuk chain tak dikenal dan wajib https) dibandingkan dengan "C2T:" + hash blok yang DIHITUNG di perangkat. Cocok + receipt sukses = Lulus; tx belum ada/belum dikonfirmasi = "Menunggu penjangkaran" (peringatan); tanpa internet = "Tidak terhubung" (peringatan); tanpa jangkar/backend lama = "Belum dijangkarkan"; data beda = Gagal. Peringatan tidak membatalkan Terverifikasi. Langkah ini hanya di Cek Keaslian (DrawController verifyOnly), tidak di Hasil Draw/cache. Tes: app\test\verify\anchor_checker_test.dart, app\test\draw_test.dart, backend\test\anchor.test.js.
- Urutan deploy: SQL migrasi 12 di Supabase -> set env di Render -> git push -> APK baru.

## Rekomendasi "Untuk kamu"
Fungsi murni `recommend()` (app/lib/features/giveaways/recommendation.dart; konstanta bobot/batas HANYA di recommendation_config.dart; tes app/test/game/recommendation_test.dart), dihitung di aplikasi dari data Home yang sudah dimuat/cache (jalan offline), tanpa perubahan backend atau migrasi SQL. Skor 0..1 per giveaway aktif = 0,4*afinitas + 0,3*kedekatan + 0,2*urgensi + 0,1*kebaruan. Lokasi tidak diketahui (tak satu pun jarak ada) = faktor kedekatan dibuang dan bobot dinormalkan. Jarak diambil dari giveaway, atau dari `DiscoverController.activeByDefault` bila mode Terdekat aktif. Cold start (afinitas kosong) = afinitas diganti popularitas (`ticket_count` relatif), bagian tampil bila >= 3 kandidat, alasan "Sedang populer". Keragaman: maks. 3 per kategori, 10 total. Alasan maks. 2 dari kontribusi terbesar (nol tidak ditampilkan). Dikecualikan: bukan fase aktif (selesai/belum mulai/lewat end_at). Syarat batas tiket per pengguna TIDAK diterapkan: `max_tickets_per_user` tidak ada di data daftar/cache. "Terdekat" dan "Segera draw" tidak berubah. `recommendFor` lama tetap hanya untuk target Buru Kode.

## Kontrak yang tidak boleh diubah diam-diam
- Password: klien menghitung PBKDF2-HMAC-SHA256 (10.000 iterasi, 32 byte, salt 32 hex dipakai sebagai TEKS UTF-8, hasil hex huruf kecil);
  server menyimpan bcrypt(hash klien). Lihat app\lib\core\crypto\password_hasher.dart dan tesnya.
- Hash block draw_chain dan algoritma pemilihan pemenang harus identik di backend dan di Dart: backend\src\lib\chain.js, backend\test\reference\test_m1.py.
  draw_chain append-only (trigger database). Seed dibuat saat giveaway dibuat; hash-nya di-commit di block pertama; seed dibuka saat draw.
- Respons API: gagal bisnis HTTP 200 {"ok":false,"error":"<kode>"}; sesi tidak valid 401 invalid_session; bukan admin 403 forbidden.
- Token session dikirim lewat header Authorization: Bearer; server hanya menyimpan SHA-256-nya; di app disimpan di flutter_secure_storage.
